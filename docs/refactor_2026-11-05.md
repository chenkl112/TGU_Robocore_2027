# 2026-11-05 自瞄分支重构记录

本轮以 `auto-aim-v0.1` 的 `e454a18` 为基线，落实 [同日审查报告](review_2026-11-05.md) 中的接口修复和维护性改进。范围包括配置、检测与解算边界、跟踪快照、规划接口、线程与设备交接、同步回放、构建和回归。用户要求的中文注释主要补在坐标、物理假设、时间和所有权边界。

尺寸假设拟合、PnP、EKF 和 TinyMPC 的已有物理模型继续保留。本轮通过拆分职责、收紧输入契约和补回归降低维护成本，没有用另一套尺寸或控制算法替换现有实现。原审查报告及复现材料描述的是修改前的行为，不能用其行号或旧接口调用代表当前源码。

## 四个已复现问题的处理

| 基线问题 | 当前行为 | 验证入口 |
|---|---|---|
| 串口发送背压期间持有云台状态锁 | 状态锁只覆盖重验证和一次非阻塞写入，等待可写期间释放；发送前检查会话、反馈和命令有效期，包前缀已发送后许可撤销则终止该串口会话 | `gimbal.backpressure_mode/timeout/alignment/deadline`、`serial.guarded_cancel` |
| 两个 `Planner::plan()` 重载有不同过期检查 | 只保留接受 `optional<TargetSnapshot>` 的公开入口，统一检查状态和最后观测时间，返回明确停止原因 | `auto_aim.planner_time_contract`、`auto_aim.planner_stop_reasons`、`auto_aim.planner_expiry` |
| 相对预测只改状态，不推进时间 | `Target::predict(dt)` 与绝对时间版本都推进状态时间；最后观测时间只在接受量测后更新 | `auto_aim.prediction_time_contract`、`auto_aim.observation_expiry` |
| ROI 记住首次或较小图像的边界 | 保存原始配置，每帧独立求有效 ROI；固定偏移、负宽高和完全落在小图外的 ROI 都可在后续大图恢复 | `auto_aim.vision_pipeline` |

新测试还发现并修复了角点改为 `std::array` 后 OpenCV 残差输入形状不一致的问题。PnP 和投影残差现在使用显式形状一致的矩阵视图，原有尺寸和透视回归继续约束结果。

## 配置和模块边界

`load_auto_aim_config()` 在正式入口只解析一次 TOML，产出分模块配置结构。模型路径、角度转换和字段验证集中在 `config.cpp`；模块的 typed 构造也做验证。布尔字段不接受整数替代，整数字段不接受布尔或浮点替代，已存在但不是表的配置段不会静默回退默认值。标定旋转、数组长度、数值有限性和错误字段名称都有对应检查。

`paths.base_dir` 未设置时沿用启动目录；设置相对值时以配置文件目录解析。模型路径加载后为绝对路径，相机文件路径使用同一资源基准，流 URL 保持原意。`auto_aim.config` 在加载后删除临时配置、切换工作目录，再构造算法对象；启用视觉的构建还构造分类器、传统检测器和 YOLO 并执行一次推理，验证正式 typed 路径不重读配置文件。

配置中的角度制字段使用 `π/180` 精确转换。`planner.fire_thresh` 原本就是弧度，保持不重复转换。反馈和重连的毫秒字段有类型、正值和表示范围检查；外部秒数与单调时钟之间的加减检查非有限值与溢出。

`Armor` 固定保存四角，基础成员和空间字段都有初值。生产跟踪通过 `Solver::resolve_observation()` 获取只读 `SolvedObservation`，避免把未解算的图像检测直接当作空间量测。兼容的原地解算接口仍保留，`pose_valid` 标识是否完成解算。

`Solver` 只组织尺寸证据与先验策略；`ArmorGeometry` 负责坐标变换、PnP、安装模型拟合、yaw 搜索和投影。布尔拟合参数改成有名称的模式枚举。世界系位姿通过同一个函数派生云台系和球坐标，朝向优化后不会留下旧的云台姿态。数字区域裁剪及 ROI 构造中的重复逻辑已合并，未使用的灯条修正私有函数已移除。

## 跟踪、规划和线程

11 维状态改用固定维度与命名索引。`Target` 持有 EKF，`TargetSnapshot` 保存控制需要的运动学值及两个时间，不携带协方差或诊断历史。Planner 的预测采样只外推快照，不重复传播 EKF 协方差。半径合法性、未来/过期时间、观测更新时间和无副作用预测有独立回归。

两根 MPC 轴由各自的 RAII 对象拥有，初始化、约束和投影逻辑统一。仍保留两轴每帧求解、既有迭代上限和热启动恢复行为。`Plan::reason` 区分无目标、时间无效、不可见、弹道不可达、未收敛和非法解；停控输出保持零。参考速度继续按同一块物理装甲求差分，避免换板造成虚假的瞬时速度。

`TrackingPipeline` 统一 Solver/Tracker 调用，实时运行和同步 `AimPipeline` 共用它。`AutoAimRuntime` 将入口中的采集、跟踪和控制循环移到明确的所有者中：推理对象只由 YOLO 工作线程使用，Tracker 只由跟踪线程使用，Planner 只由控制线程使用。控制线程通过 `LatestValue` 获取独立快照，并在取得快照和反馈后读取本次规划时钟。

有界队列支持关闭、停止令牌、排空和移动值；满队列回调在锁外运行。推理输入/输出容量均为 2，满时丢最旧帧。`MultiThreadYOLO` 使用显式停止与队列关闭，工作线程异常转交给消费者；不再依赖空图像作为退出暗号。Runtime 统一停止自己的循环，姿态等待支持取消，析构负责回收设备和推理线程。

控制循环以 10 ms 截止时间推进，超期后跳过错过的周期。退出时记录周期数、错过次数、最大计算时间、发送间隔和目标年龄。指令携带 `valid_until`，发送边界在实际写入时再次判断新鲜度；等待串口不延长观测有效期。

## 同步回放和性能边界

`AimPipeline::step()` 按一帧一次的顺序执行检测、跟踪和规划，使用录包时间判龄。CLI 支持 `--headless=true`、帧范围、推理设备覆盖和 CSV 导出；帧范围跳转同步消费位姿记录。重复时间、非法四元数、位姿缺失或数量不一致会报错。

CSV 保存目标选择、跟踪状态、11 维状态、状态/观测时间、控制量和停止原因。CLI 不提供实际云台反馈，因此只能输出控制计划，`fire` 为假。输出先写同目录临时文件，正常结束后原子替换；异常会保留既有 CSV。录包、配置、模型及 XML 对应权重文件受覆盖检查保护，包括符号链接和硬链接指向的同一文件。

推理请求和输入缓冲区改为每个检测实例复用，并在每帧清空补边。真实模型的 ROI 分辨率往返测试、空图像和异常输出测试检查复用边界；分类器检查九类有限输出，后处理不再修改调用方 tensor 的形状。

本轮没有替换尺寸拟合的多初值、数值差分或 yaw 搜索范围，也没有加入投影缓存或更少候选点。状态已固定维度，但装甲候选列表仍使用现有容器。控制周期统计已加入，检测、解算各阶段的实机耗时及优化前后吞吐对照尚未测量，不能据此给出提速比例或端到端延迟结论。

## 构建、文档和持续集成

[cmake/RobocoreTargets.cmake](../cmake/RobocoreTargets.cmake) 统一声明配置、数学、算法、视觉、设备和 Foxglove 库。自动化测试链接相同生产库，独立测试目录也复用这份目标定义。纯算法开关可关闭视觉、设备及 Foxglove，显式禁止查找 OpenVINO/Boost/PkgConfig；完整构建保留真实模型和进程测试。Aravis 仅由单独的相机演示开关引入，Foxglove SDK 文件继续保留。

测试按跟踪、规划、几何/设备和时间契约拆分，测试目标通过明确的快照夹具构造，不再通过 `const_cast` 修改 EKF 内部状态。新增配置、通道和真实模型完整正例测试；原强透视、噪声、尺寸、旋转目标、MPC 失败恢复和串口生命周期回归继续保留。

格式以现有 `.clang-format` 为准，`tools/check_format.py` 使用固定的 `clang-format 23.1.5`，排除第三方实现和历史复现源码。GitHub Actions 工作流定义了格式检查、完整 Release、隔离核心 Debug 和独立 IO AddressSanitizer/UBSan 四条任务。工作流文件的加入不代表已经取得远端运行结果。

[README](../README.md) 与 [英文版](../README.en.md) 同步了构建及回放命令；`README.zh-CN.md` 指向主中文文档，避免重复维护。模块说明补齐类型、单位、坐标、物理假设、线程和退出契约。原结构规范保留为明确标注的历史原稿，页首先指向现行说明。
