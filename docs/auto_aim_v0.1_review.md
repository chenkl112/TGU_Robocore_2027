# 装甲板自瞄 v0.1 评审与发展路线

## 1. 版本定位

v0.1 是 `sp_vision_25` 装甲板自瞄向 TGU Robocore 框架迁移后的首个基线版本，
面向当前联盟赛需求，仅允许以下机器人目标：

- 英雄（1 号）；
- 工程（2 号）；
- 步兵（3、4、5 号，含两块装甲板的平衡步兵）；
- 哨兵。

前哨站、基地、负样本不会进入跟踪器；仓库中不包含能量机关识别、预测或任务入口。
下位机协议中的小符/大符模式枚举仅为兼容已有通信协议保留，进入这些模式时不会运行
能量机关算法，也不会输出自瞄控制。

## 2. 已完成的适配

- 按 `app`、`io`、`tools`、`task` 的框架边界拆分算法、设备和正式入口。
- 迁移 YOLOv8/OpenVINO、数字分类、PnP、整车 EKF，以及原版
  `standard_mpc` 的 Planner/TinyMPC；正式入口输出角度、角速度和角加速度。
- 保留传统 Aimer/Shooter 源码作为备用链路，当前正式入口不调用它们。
- 使用统一的 `is_robot_target()` 白名单约束传统检测器、YOLO 和 Tracker，并用
  `static_assert` 固定排除前哨站、基地和非装甲类别。
- 保留大小装甲板判断，并恢复平衡步兵的双装甲板整车模型入口。
- 修复 PnP 失败继续使用结果、两装甲板候选越界、NIS 时序、固定分辨率中心点、
  重复分类器构造和不可解弹道未检查等问题。
- 相机采图使用新帧通知，避免同一帧被反复消费；相机来源、分辨率和帧率移入 TOML。
- 云台串口打开失败改为异常；首个有效数据包增加超时；四元数会校验、归一化并按
  相机时间戳插值。
- 默认关闭自动发弹；手动开启后使用原版 MPC 参考轨迹与求解轨迹的误差门限判定。
- 补齐 CMake target、第三方许可说明、格式规范、运行配置和离线回放入口。

## 3. 当前不足和风险

### P0：上车前必须解决

1. **实机标定尚未完成**
   当前内参、畸变和相机到云台外参来自迁移参考，只能用于代码联调。必须使用本队实际
   相机、镜头、安装位姿重新标定，否则 PnP、世界坐标和射击角都会产生系统误差。

2. **串口协议尚未与下位机逐字段确认**
   需要核对帧头、结构体字节数、大小端、CRC 范围、角度单位、角速度/角加速度单位、
   四元数顺序以及发弹模式值。确认前保持 `[planner].auto_fire = false`。

3. **尚未完成实机运行验证**
   已在 Ubuntu 24.04、GCC 13 和 OpenVINO 2026.3 环境完成 Release 干净构建及模型加载，
   但仍需连接实际相机、串口和云台验证运行时序、控制方向与发弹链路。

4. **没有本队录包回放数据**
   离线测试入口需要同步的视频与 IMU 四元数文本。没有覆盖静止、平移、旋转、遮挡、
   交叉目标和强光场景的数据，就无法证明跟踪与预测性能。

### P1：首轮场地调试应解决

1. **目标切换策略仍缺少滞回**
   当前已恢复原版的两套兵种优先级，同优先级目标按画面中心选择，出现更高优先级目标时
   立即切换。后续仍需结合距离、连续锁定时间、装甲板朝向和裁判系统血量，并增加切换滞回。

2. **弹道模型只考虑重力**
   远距离和弹速变化下需要加入空气阻力或实测查表，并对弹速反馈做滤波，避免单帧异常
   触发明显俯仰跳变。

3. **端到端延迟未在线估计**
   当前延迟由高低转速两个常数近似。应分别测量曝光、采集、推理、通信、执行和发弹延迟，
   使用时间戳在线补偿。

4. **MPC 参数尚未实车整定**
   当前 Q/R、角加速度约束和发弹阈值来自 `sp_vision_25` 的 `standard_mpc`。
   这些参数与云台惯量、下位机控制器和通信周期耦合，必须在禁弹状态下重新整定。

5. **关联策略仍以类别和装甲板类型为主**
   多个同号目标靠近或交叉时可能错误关联。应加入马氏距离门控、图像位置、距离和外观置信度。

6. **退出与故障恢复不完整**
   正式入口是常驻循环，后续应接入 SIGINT/SIGTERM、安全停控、相机重连状态和串口断线重连。

### P2：工程质量改进

- 为 Tracker 状态机、弹道边界、目标白名单、PnP 失败和串口打包增加自动化测试。
- 在 CI 中加入 Release/Debug 构建、`clang-format`、静态分析和 TOML 配置检查。
- 将 OpenVINO 固定输出形状、分类标签顺序和模型哈希写入模型清单，启动时快速失败。
- 确认 YOLO 模型元数据中声明的 AGPL-3.0 义务，以及数字分类模型的来源和许可。
- 增加 Foxglove 调试数据：检测框、PnP 重投影、EKF 状态/NIS、MPC 参考/求解轨迹、
  角速度、角加速度、延迟分解和发弹门限。

## 4. 建议的发展版本

### v0.2：可重复离线验证

- 建立本队同步录包格式与至少 10 个典型场景的数据集。
- 增加检测准确率、PnP 重投影误差、跟踪丢失率、角度预测误差和单帧耗时统计。
- 支持 TOML 自定义兵种优先级，并增加目标切换滞回和 ROI。
- 建立 GitHub Actions 或队内 CI，保证每次提交能干净构建并运行单元测试。

验收建议：机器人目标误收前哨/基地为 0；典型数据集连续跟踪成功率不低于 95%；
所有离线指标可由单条命令复现。

### v0.3：实机闭环调试

- 完成本队相机内参与手眼标定，并保存标定日期、设备序列号和重投影误差。
- 校准上下位机坐标系、单位和时间戳，测量端到端延迟。
- 用实测弹道或阻力模型替代纯重力模型，按距离和弹速验证补偿。
- 在摩擦轮关闭、供弹关闭、低速云台三个阶段逐级验证控制与发弹门限。

验收建议：静态目标平均角误差小于 0.3°；3–8 m 距离内 90% 分位角误差小于
0.6°；任何无目标、模式切换、串口断开场景均不允许发弹。

### v0.4：比赛鲁棒性

- 加入同号多目标关联、遮挡恢复、置信度衰减和目标切换策略。
- 通过异步推理、预分配和硬件后端选择稳定帧率，并记录最坏延迟而非只看平均值。
- 加入进程看门狗、设备自动重连、配置版本和模型哈希日志。
- 用真实联盟赛录像做长时间回归测试。

验收建议：连续运行 30 分钟无崩溃、无死锁、无内存持续增长；P99 处理延迟满足
云台控制周期；故障恢复后保持禁射直到重新建立有效跟踪。

### v1.0：可比赛交付

- 冻结协议、坐标系、配置模板和模型版本。
- 完成全套硬件在环、场地光照、运动目标和安全回归测试。
- 输出一键部署/启动脚本、参数说明、标定流程、故障排查和比赛检查清单。
- 只在量化指标达标并通过机械、电控和算法三方评审后开启默认比赛配置。

## 5. v0.1 建议验收命令

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
./build/auto_aim_test --config-path=config/auto_aim.toml <recording-prefix>
```

上车前还应人工确认：

- `enemy_color` 与比赛方颜色一致；
- 配置中的标定参数属于当前设备；
- 云台反馈和控制角度均为弧度；
- 四元数顺序是 `w, x, y, z`；
- 自动发弹仍关闭，直到完成分阶段安全验证。
