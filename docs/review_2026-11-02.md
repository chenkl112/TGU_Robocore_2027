# 自瞄分支代码审查与 P1 修复

审查基准为 `auto-aim-v0.1` 的 `9e0f1aa1cdc0f56f3872323a0581736c6524cc9c`，修复分支为 `fix/full-review-p1`。本次检查该基准的全部项目代码、构建入口、配置、模型接口和文档；`main` 的 Point-LIO/MID360 代码不属于这次自瞄分支审查。

检查沿实际调用链展开：`auto_aim_sentry`、USB 相机、YOLO/OpenVINO 与数字分类、PnP、Tracker/Target/EKF、Planner/TinyMPC、Gimbal/Serial；同时检查离线回放、备用 Aimer/Shooter、Foxglove/日志、工具和测试入口。仓库包含的 Foxglove 二进制库与模型权重通过接口、许可说明及模型运行检查覆盖，未重新审计其上游实现或训练数据。

本次确认并修复下列 **11 组 P1 缺陷**。这里的 P1 指应在下一轮使用前修复的代码缺陷；原 v0.1 文档中的实车整定、阻力弹道等研发任务仍按其原有验收条件执行。

| 编号 | 原行为与影响 | 修复位置和行为 | 验证 |
|---|---|---|---|
| P1-01 | 规划线程反复读取队列首项，相机、推理或跟踪停滞后仍无限预测旧目标，自动发弹打开时可能沿用旧目标开火。 | `planner.cpp` 校验目标时间，正式入口在发送前再次校验；默认超过 100 ms 停控。 | `auto_aim.planner_expiry`、正式入口发送前检查 |
| P1-02 | 云台停止反馈仍保持最后的 AUTO_AIM；IDLE/AUTO_AIM 往返也可能复用上一次目标。检查模式与发送之间存在切换窗口。 | `gimbal.cpp` 对反馈设置 100 ms 有效期；模式变化或断流恢复创建新会话。入口丢弃会话开始前的帧并重置 Tracker；发送在同一把锁下核验会话、模式和反馈。 | `gimbal.feedback_timeout`、`gimbal.mode_session` |
| P1-03 | `Gimbal::q()` 消耗历史队列并无限等下一条 IMU，断流时卡住；同一时间段内后续帧也会失去插值所需的前后样本。 | 改用保留历史的查找和有期限的条件变量等待；拒绝历史之外的时间戳及跨断流间隔插值。 | `gimbal.pose_history` |
| P1-04 | `detecting` 阶段已经向 Planner 返回目标，`min_detect_count` 没有阻止单帧控制；高优先级切换绕过确认；暂丢目标仍可发弹。 | `tracker.cpp` 仅在完成连续确认后输出目标；切换重新确认；Target 标记本帧是否成功观测，暂丢阶段保持预测控制并禁射。 | `auto_aim.tracking_confirmation`、`auto_aim.priority_switch`、`auto_aim.lost_target_fire` |
| P1-05 | TinyMPC 只迭代 10 次，入口读取未投影的 `work->u`，忽略求解状态。1 m、10 rad/s 的自检中，配置上限 50 却输出 yaw 加速度 63.245 rad/s²。 | `planner.cpp` 使用投影后的输入，并重建对应的角度/角速度轨迹；未收敛时禁射。相同输入修复后输出 50.000 rad/s²。 | `auto_aim.planner_acceleration_bounds` 覆盖 0–100 rad/s 的多种角速度 |
| P1-06 | 所有同类别、同装甲类型的观测都进入同一个 EKF，远处同号机器人也被合并更新。 | `Target::update()` 在更新前校验与预测装甲板的空间残差；默认最大 0.5 m，可配置；被拒观测不推进确认状态。 | `auto_aim.association_gate` |
| P1-07 | 同步串口读写可无限阻塞；close/open/read/write 共享状态无保护；静态模板解析器在多串口和多个订阅之间串流，重开还保留旧半包。 | `serial.cpp/.hpp` 使用非阻塞读写、有期限的 poll、会话隔离与互斥；解析器按订阅独立持有，重开清空旧会话残留。 | 14 项 `serial.*`，包含写堵塞、静默读取、断连、重开、多端口和并发 |
| P1-08 | 工作线程异常触发 `std::terminate`，绕过安全停控；正式入口没有可达的退出路径；相机等待可能阻止线程回收。 | 捕获并转交 YOLO/入口线程错误；SIGINT/SIGTERM 触发停控和 join；相机消费等待有期限，V4L2 使用有期限的 `waitAny`，FFmpeg 设置打开和读取超时。 | `auto_aim.worker_failure`、`auto_aim.camera_timeout`、`runtime.signal_shutdown`、`runtime.missing_camera`、`runtime.network_camera_silence` |
| P1-09 | 缺失标定被替换成单位矩阵；退化 PnP、NaN 弹速/状态可继续生成控制；无穷角度进入循环归一化后无法退出。 | `solver.cpp` 严格检查标定、旋转矩阵、四元数和 PnP；Planner/弹道拒绝非有限输入；角度归一化改为常数时间实现；发送端拒绝任何非有限控制值。 | `auto_aim.calibration_validation`、`auto_aim.pose_validation`、`auto_aim.invalid_numeric`、`auto_aim.trajectory`、`gimbal.mode_session` |

| P1-11 | Logger 在锁外读取 `level_`，与并发 `init()` 写入构成数据竞争。 | 将过滤检查移入互斥区；同时修复反复初始化时文件流未关闭/清状态导致日志丢失的问题。 | 7 项 `logger.*`，含并发初始化/写入及文件切换 |

Planner 的两个求解器也补上了析构和初始化失败时的回收，避免重复创建对象泄漏。顶层 CMake 已接入 CTest；测试可以单独构建串口、日志及不依赖模型的自瞄部分。

验证环境为 Linux、GCC 13.3、OpenCV 4.6、Eigen 3.4、Boost 1.83、OpenVINO 2026.3。由于当前环境没有系统开发依赖且不能免密 sudo，本次将发行版开发包解压到仓库外的临时目录，并在独立 Python 环境中安装仓库固定的 OpenVINO 版本；未把本机依赖路径写进项目。

Release 全量构建成功，顶层 CTest **42/42 通过**：日志 7 项、串口/云台 19 项、自瞄数值/状态 11 项、OpenVINO 工作线程 1 项、正式入口/回放进程 4 项。工作线程测试先实际推理一帧 BGR 图像，再注入无效格式，验证错误能唤醒阻塞的消费者。串口/云台另以 AddressSanitizer + UndefinedBehaviorSanitizer 执行，**19/19 通过**。

安装 README 所列依赖后，从仓库根目录复现：

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j4
ctest --test-dir build --output-on-failure -j4
./build/planner_test --config-path=config/auto_aim.toml --distance=1 --angular-speed=10
```

进程测试用 Python 标准库创建伪串口和静默 HTTP 服务，用 OpenCV 生成临时视频。回放测试通过 Qt 的 offscreen 平台运行，需要发行版 OpenCV/Qt 的该插件。测试文件和临时配置会自动清理。

单独复现串口与云台的内存/未定义行为检查：

```bash
cmake -S tests/io -B build-io-asan -DCMAKE_BUILD_TYPE=Debug -DIO_SANITIZER=address
cmake --build build-io-asan -j4
ctest --test-dir build-io-asan --output-on-failure -j4
```

仍需处理的 P2 与实车验证条件：

- 0.5 m 的空间门控不能区分彼此贴近的同号目标；完整交叉目标关联、切换滞回和外观/协方差门控仍需数据集验证。
- 弹道仍只有重力模型，延迟仍使用常数补偿；未测量曝光、传输、推理、下位机执行和供弹的实际延迟。
- 串口故障会停控并进入 IDLE，尚未自动重新打开设备；重连策略和进程看门狗仍需补齐。
- 备用 Shooter 只检查 yaw 对齐，未校验 pitch；正式入口未调用该链路，启用前需补齐。演示用 `test_serial` 没有填写发送 CRC，`read_toml` 仍依赖固定相对路径，应作为后续测试入口清理项。
- 模型缺少哈希清单，模型来源/许可仍应按 `LICENSES/README.md` 核对；CI 尚未自动执行本次测试。
- 未连接真实相机和云台，未使用本队标定/录包，也未进行闭环控制或真实发弹验收。默认 `auto_fire = false`。软件停控包不能替代下位机在通信中断时自身禁射的逻辑。
